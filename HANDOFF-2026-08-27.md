## 3. The owner's decisions taken in this window

All confirmed 2026-08-24 during the brainstorm, recorded in the spec and
ADR-010; none should be re-derived or re-asked:

1. **A source is a typed citation, not an uploaded file.** Шифр/назва
   документа, аркуш and номер креслення are mandatory; ревізія optional.
   «Робоча документація» without a sheet and a drawing number is a word, not a
   source — INV-073's letter.
2. **Workspace-scoped with `project_id NOT NULL`.** Cross-project binding is
   deliberately not forbidden; the citation travels with the text.
3. **A separate table** (`project_sourced_requirement_items`), so authoring
   cannot corrupt the seeded verified set even in principle.
4. **The value is `PROJECT_DOCUMENTATION`**, its UI label is
   **«за робочою документацією об'єкта»** — an origin, never «перевірено» in
   any form. `UNVERIFIED` and this value must never be conflated: one is a
   string nobody sourced, the other is sourced to a named sheet.
5. **The capability (`project_requirements.manage`) is held by exactly the
   roles that hold `requirement_rules.manage`** (owner/admin).
6. **The external технагляд sees project-sourced requirements** — the
   acceptance walk is the product thesis, so `externalNormRef` was widened
   rather than the grant refused.
7. **No dashboard screen.** The whole authoring path is API-only, like
   `requirement_rule_versions.publish` before it. A screen is a separate
   decision with four named prerequisites (TODOS residual 1).

## 4. What shipped, and the three defects that never reached a user

One slice, change-control order: ADR-010 → the Approved content-rules edit →
catalogs (three `project_requirements.*` rows, the capability, the entity, the
counts moved in four places — two of which the validator does not check) →
migration `0059` → the three-value `verificationTag` stated once per package →
three routes → the publish command's second source arm with the citation
frozen into the rule-version hash → an end-to-end test to the external
reviewer → the fifth mandated disclaimer actually rendering.

The review loops caught these **before merge**; each is the kind that reaches
a user quietly:

- **The tenant check that rode the wrong policy.** The create route verified
  «does this project belong to this workspace» by reading `public.projects`
  under `projects_select` — a policy that answers a different question, «may
  this member see this project's contents», via the per-project ACL
  (INV-019: only the creator is auto-granted). A workspace admin who had not
  personally created the project got a spurious 422 «Проєкт не знайдено». The
  test suite was green because its fixture had the same user create the
  workspace and the project. Fixed with `app.project_in_workspace` (definer,
  boolean-only) and a non-creator-admin regression test. The lesson is a
  sentence: *an RLS policy's question is not your question until you have read
  the policy.*
- **The archive that raced itself.** `app.archive_project_sourced_requirement_item`
  SELECT-checked status, then UPDATEd without a status filter; two concurrent
  calls to an idempotency-required operation left the loser raising P0001
  through the guard instead of being the promised no-op. Fixed with a
  compare-and-swap (`and status = 'active'`), pinned by a race test that
  **forces** the interleaving by polling `pg_stat_activity` for the blocked
  backend — the first, timing-based version of that test passed against the
  unfixed function. *A concurrency test that isn't forced is a test that can
  pass on the bug.* The same unguarded shape exists upstream in
  `app.retire_requirement_rule_version` — residual, §5.
- **The mandated disclaimer that nothing printed.** The Approved document now
  requires a note under any requirement list that carries project-sourced
  items. The constant existed, modelled but unrendered, defended by a comment
  claiming the surface was unreachable in v0.1 — while act composition selects
  decisions from occurrences **with no provenance filter**, and this same
  slice made a project-sourced occurrence storable. The final whole-branch
  review proved the surface live and refuted the controller's own recorded
  ruling; the disclaimer now renders whenever at least one decision carries
  the tag (the doc says «also carries» — one is enough, mixed is not
  required), with the prohibition-E sweep guarding it citation-aware.

Also fixed at the same review: three sites over-claiming «exactly one source,
enforced by a CHECK» — the database CHECK enforces **at most** one (neither is
storable); exactly-one lives on the wire, in the request's superRefine. The
corrected wording is «at most one in the database, exactly one on the wire».

## 7. How this session worked, and the failure modes it hit

Orchestrated subagents, one implementer per task or batched unit, a task
review after each, scoped re-reviews per fix round, one final whole-branch
review, models sized to the work. The loops were not ceremony:

- **Two controller claims were refuted by evidence, and both refutations were
  accepted.** The previous handoff's «no write plumbing at all» fell to a read
  of `grants.service.ts`; the controller's own «the disclaimer's surface is
  future» fell to the final review reading `statutory-act.ts`. The rule that
  survives both: *a ruling about what code does is a claim, and claims lose to
  files.*
- **The cheapest model fabricated confidently.** A TODOS entry drafted by the
  fast tier invented an ADR filename, an expansion of ПТВ, a route path, a
  file that does not exist, a milestone narrative for migrations it never
  read, and a CI run during the billing pause. Caught because the controller
  read the diff before committing, fixed by dictating verified facts.
  Delegation does not delegate the §7 rules; **the controller reads every
  diff it commits.**
- **The NBSP rule caught its own author twice.** A literal non-breaking space
  was pasted into the plan once and into a TODOS quote once — the exact
  invisible-in-diff failure 0052 documents. Both caught by byte-level checks,
  which is the only way they are ever caught.
- **Environment facts worth keeping:** `@goproceed/testing` and
  `apps/app` test suites must never run concurrently against the shared local
  database (deadlocks, vanished fixtures — observed, not theorized). The
  `SUPABASE_DB_URL` port is **54322** both locally and in CI (ci.yml runs the
  same supabase local stack). And
  `supabase db reset` wipes the dev role passwords —
  `pnpm -w db:local-credentials` after every reset.
- **The gate was run by the controller, not accepted from a report**, per the
  standing rule: `supabase db reset` from zero through `0059` clean;
  `pnpm validate:canonical-docs` → OK; `pnpm turbo run typecheck` green;
  `pnpm turbo run test --concurrency=1` green across all packages — the
  serialization is load-bearing, see the environment fact above.
