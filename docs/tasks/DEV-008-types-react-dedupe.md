**The forced-order script** (run from a checkout with dependencies installable from the store; it deletes every `node_modules`):

```bash
SLOW="apps/app apps/landing packages/ui"
rm -rf node_modules apps/*/node_modules packages/*/node_modules discovery/node_modules
for p in $SLOW; do rm -f "$p/.npmrc"; mkfifo "$p/.npmrc"; done
( sleep 3; for n in $(seq 1 40); do for p in $SLOW; do ( exec 3>"$p/.npmrc" ) & done; sleep 0.5; done ) &
FEEDER=$!
pnpm install --frozen-lockfile --reporter=silent; kill $FEEDER; pkill -f "exec 3>"
for p in $SLOW; do rm -f "$p/.npmrc"; done
readlink node_modules/.pnpm/node_modules/@types/react
(cd apps/landing && ../../node_modules/.bin/tsc --noEmit --incremental false | grep -c 'error TS')
```

Rework count and hypothesis changes: the first hypothesis, that pnpm's hoist is a deterministic function of the lockfile, was dropped after reading `hoistGraph`'s input order (Progress row 3).

## What is not true after this task

- **pnpm 9.12.0's order-dependent private hoist is still there.** Any other package that reaches two versions in the lockfile and is imported through the hoist can do the same. Nothing checks that the lockfile keeps one `@types/react`; BL-083 files a guard.
- **Packages still import `@types/react` they do not declare.** `next`, `lucide-react`, `framer-motion` and `@tanstack/*` reach it through the hoist; with one version that is harmless, not removed.
- **No `pnpm.overrides` was added.** A future `apps/mobile` pin (for example from `expo install --fix`) can split the version again.
- **pnpm is not upgraded,** and the «pnpm v10 installation layout» warning from `pnpm/action-setup` remains; it did not cause this.
- **`apps/landing`'s `incremental: true` and `.next/types/**/*.ts` include are unchanged;** they did not cause this.
- **No test suite ran locally** (root `AGENTS.md`); CI's `verify` runs them. `pnpm --filter @goproceed/mobile qa`, `expo install --check` and a device build were not run; the change is types-only for `apps/mobile`.
