# 00. Product brief

## Продукт одним предложением

AktFlow показывает специализированному субподрядчику, какие выполненные работы готовы к предъявлению и оплате, а какие деньги остаются под риском из-за недостающих доказательств, документов или согласований.

## ICP v1

- Электромонтажный субподрядчик в Украине.
- 15–100 сотрудников, 2–10 активных объектов.
- Контракты с генподрядчиками/коммерческими или публичными заказчиками.
- Поэтапная оплата, АВР, исполнительная документация, скрытые работы.
- Использует Excel + Telegram/Viber + Drive + АВК/BAS.
- Имеет хотя бы одного PM/инженера ПТО/сметчика.

## Пользователи

| Роль | Работа в AktFlow | Ценность |
|---|---|---|
| Собственник/коммерческий директор | Смотрит деньги под риском и aging | Контроль cash flow и приоритетов |
| Руководитель ПТО | Настраивает требования, проверяет пакет | Меньше возвратов и ручного chase |
| Project manager | Управляет объёмами, изменениями, согласованиями | Закрытие месяца без сюрпризов |
| Прораб/бригадир | Фиксирует объём, фото, голосовой комментарий | 30–60 секунд вместо чатов и Word |
| Сметчик/биллинг | Формирует пакет и экспорт | Перенос данных без повторного ввода |
| Внешний reviewer/генподрядчик (GA) | Просматривает/подтверждает по secure link | Не нужен аккаунт и новое ПО |

## Core loop

1. Импорт договора и schedule of values/локальной сметы.
2. Назначение evidence rule set каждому виду работ.
3. Создание конкретных заданий по позиции, локации, объёму, исполнителю и сроку.
4. Разворачивание повторяемых requirements по location/date/batch/quantity trigger и полевой capture.
5. Автоматическая проверка комплектности + review человеком.
6. Выявление изменений/допработ до закрытия конструкции.
7. Формирование пакета периода и экспорт в привычные системы.
8. Получение решения, исправление возвратов, отслеживание оплаты.
9. Причины возвратов агрегируются в отчёты recurring causes (versioned reason codes → `package_returned.reason_code`, `review_returned.loop_count_bucket`); правила меняет администратор вручную новой версией. Автоматического «обучения» правил нет ни в Pilot, ни в GA-core (см. реестр обещаний, doc 37).

## North-star metric

**Value of evidence-ready work submitted through AktFlow per month** — сумма работ, чья readiness перешла из `evidence_missing`/`review_pending` в `packaged` и вошла в поданный пакет периода (`submitted`); термины — из `technical/state-catalog.csv`.

Guardrails:

- median time from performed → ready;
- % work value returned из-за недостающих доказательств;
- field capture completion rate;
- sync failure rate;
- доля ручных override;
- доля пакетов, прошедших без повторной подачи.

## MVP promise

> За 30 дней на одном объекте AktFlow создаст единую картину готовности к закрытию и снизит количество позиций, обнаруженных без доказательств в конце периода.

Не обещаем:

- гарантированную оплату;
- юридическую силу любого типа доказательства;
- автоматическое принятие заказчиком;
- замену сметчика, ПТО или юриста.

## MVP scope

- multi-tenant organization;
- web back office;
- iOS/Android Expo field app (Android-first rollout приоритет);
- импорт XLS/XLSX/CSV;
- объект, контракт, work item, location;
- versioned contract terms: reporting/cutoff/notice/payment/retention/document policy;
- work assignment/capture task с одним assignee в Pilot, плановым объёмом и due window;
- versioned evidence templates;
- requirement occurrences и before-concealment hold points;
- фото, файл, голосовой комментарий, quantity и versioned typed evidence forms;
- controlled reference documents/revisions без BIM/CDE authoring;
- offline outbox + resumable upload;
- completeness/readiness engine;
- risk register по сумме;
- review/approval внутри компании;
- evidence request с назначением и неизменным blocker;
- period package и PDF/XLSX/ZIP export;
- ручная фиксация подачи и построчного внешнего решения без отправки из AktFlow;
- immutable audit events;
- in-app уведомления, read receipts и versioned preferences;
- общий `plan_version + subscription + override` контур, payment request и ручная one-invoice сверка оплаты.

Variations, secure external review, project receivables/retention/payments, self-service plan changes и внешние notification providers предусмотрены в модели и прототипе, но остаются GA-функциями за release gates.

## Non-goals до PMF

- полноценное создание смет;
- бухгалтерский учёт/налоги/зарплата;
- закупки и склад;
- BIM viewer;
- календарно-сетевое планирование;
- распознавание качества работ по фото;
- marketplace субподрядчиков;
- финансирование/факторинг;
- автоматическая юридическая претензия;
- универсальная система генподрядчика.

## Почему сейчас

- Украина цифровизирует строительные документы и акты, включая обмен JSON/XLS/XLSX через ЄДЕССБ.
- Существующие локальные решения разделены между полевыми отчётами и проверкой уже готовых АВР.
- Глобальные продукты подтверждают спрос, но ориентированы на AIA/SOV/T&M и формы США/Запада.
- Субподрядчику нужен собственный переносимый record независимо от инструментов разных генподрядчиков.

## Kill criteria

Остановить или перепозиционировать продукт, если после 15–20 качественных интервью и 3 concierge-аудитов:

- меньше 3 компаний готовы показать реальный closing workflow и предоставить артефакты (порог согласован со Stage-0 gate в doc 12);
- ни одна не оценивает задержанный/рисковый объём минимум в 10× стоимости пилота;
- ни одна не готова заплатить 15–30 тыс. грн за один объект;
- полевая фиксация требует больше 90 секунд на типовую работу;
- генподрядчик всегда навязывает собственную систему и запрещает независимый record;
- причины задержек в основном не документальные, а исключительно отсутствие финансирования.
