# Expo HAS CHANGED

Read the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing any code.

## Platform positions that app.json cannot express

Two settings a reviewer will look for in `app.json` are deliberately absent,
because SDK 57 removed the keys rather than changing their defaults. Checked
against `@expo/config-types@57.0.2` — the schema this project actually resolves —
where neither key exists at any nesting level.

- **New Architecture: ON, and not configurable.** SDK 55 and later run entirely
  on the New Architecture; React Native 0.82 removed the switch. `newArchEnabled`
  is ignored where it still appears, and the docs say to delete it. Adding
  `"newArchEnabled": true` would read as a decision this project made and can
  revisit — it is neither. If you need the legacy architecture you need SDK 54,
  not a config key.
- **Android edge-to-edge: ON, and not configurable.** `android.edgeToEdgeEnabled`
  was removed in SDK 56; edge-to-edge is mandatory when targeting Android 16+.
  Nothing needs declaring, and `expo-navigation-bar`/`expo-status-bar` methods
  that fought it are no-ops now. Screens must assume content renders under the
  system bars and use `react-native-safe-area-context` for insets — B0's one
  screen has no bar-adjacent content, so it does not yet.

Unverified here: both statements are read from the SDK 57 schema and docs. This
project has no device, no Apple/Google/Expo account, and never runs `eas build`,
so neither has been observed on real Android or iOS hardware.

## Typed routes are weaker in CI than in your editor

`experiments.typedRoutes` is on, and it works: with types present, `<Link
href="/no-such-route">` is a `tsc` error. But the types live in
`.expo/types/router.d.ts`, which is **generated by `expo start` and gitignored**.
On a clean checkout that file does not exist, and `pnpm typecheck` accepts a
bogus href silently — verified, not assumed. That is Expo's own shipping
arrangement, not a local misconfiguration. Treat route-typo safety as an
editor/dev-server guarantee, and do not cite `pnpm typecheck` as the thing that
enforces it.

## Structure

`src/app` is the route table and holds nothing else. Screen bodies live in
`src/screens` and are imported by a route. A file added to `src/app` is a URL.
